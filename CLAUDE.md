What this is**Nexus** is a **Windows 11 desktop app** (Electron + React + TypeScript) — a **command center for AI**. It:* **Discovers and controls AI models across the user's WiFi/LAN** — Ollama on their PC and other machines —plus optional **cloud** models (OpenAI / Anthropic / xAI).* **Orchestrates** them (planner → coder → reviewer) to work on a project folder, once or continuously.* Exposes an **MCP server** so Claude Code can drive the local models, and a **Discord** webhook + control bot.* Includes **Jarvis**, an in-app desktop assistant you talk/type to that acts on the PC.### Names \& identifiers* **Product name: Nexus.** The in-app assistant is **Jarvis**. Architecture \& conventions (important)* **`src/main/` core modules are Electron-free on purpose** (`ollamaClient`, `providers`, `discovery`,`orchestrator`, `continuous`, `fileTools`, `git`, `commands`, `prompts`, `fileBlocks`, `runStore`,`notifier`, `actions`) so the MCP server, CLIs, and tests reuse them. **Keep them free of `electron`imports.** Electron-bound glue lives only in `index.ts`, `chat.ts`, and `desktop.ts`.* **IPC pattern:** channels are constants in `src/shared/ipc.ts`; `preload/index.ts` exposes a typed`window.api`; the renderer NEVER imports electron. **Adding an IPC = channel → main handler → preloadmethod → renderer use** (all four).* **Event-ordering gotcha:** handlers that stream events (chat, orchestrator, continuous, Jarvis) start thework inside `setImmediate(...)` so the `invoke` returns its id BEFORE the first event fires, or therenderer drops early events.* **Injectable seams for tests:** `runCollaboration(..., { ask })`, `runContinuous(..., { ask, git })`.Tests inject fakes; `index.ts` injects `unifiedAsk` (cloud-aware, from `chat.ts`) and the real git.* **Sandbox / safety:** agent file writes go through `ProjectFiles` (path-traversal rejected). Shellcommands (`commands.ts`) are **off by default**, single-command-only (metachars rejected), allowlist +approval. Cloud/Discord secrets live only in electron-store or env — **never committed, logged, or acceptedinto the transcript.*** **Settings** are DEEP-merged in `store.getSettings()` so new nested keys backfill for existing users(`temperatures`, `promptOverrides`, `continuous`, `cloudProviders`, `jarvisApps`).* **Renderer state:** theme / nicknames / snippets / last-task / Jarvis-accepted / Jarvis-speak use`localStorage` (keys prefixed `laic.`); everything else via the settings IPC.### Feature notes* **Small-model helper** (`prompts.ts`): house-rules preamble + few-shot `FILE:` example + low temperature +**auto-repair** (one corrective re-ask if the coder emits no parseable `FILE:` blocks). `fileBlocks.ts`closes on the LAST fence so READMEs with inner fences aren't truncated. Coder may also emit `RUN: <cmd>`.* **Continuous** (`continuous.ts`): externalized memory under `<projectRoot>/.localai/` (`goal.md`,`plan.md`, `progress.md`); a "lead" picks the next step; each changed cycle is git-committed; stall guardpauses after N no-change cycles.* **Cloud** = pseudo-instances with `baseUrl` `cloud:<provider>`; keys in `settings.cloudProviders`. Excludedfrom LAN scan/health poll. `chat.ts` routes them. Model ids go stale — update on a 404.* **Jarvis** (Stage 1): the model emits `ACTION: <name> {json}` lines (one per line). `actions.ts` parses +gates; `index.ts#runJarvisAction` executes via `desktop.ts` — `open\\\\\\\_url`, `open\\\\\\\_app` (from`settings.jarvisApps`), `create\\\\\\\_document` (→ `\\\\\\\~/Nexus/`), `say`, and `run\\\\\\\_command` (reuses the gated shellrunner). Gated on `jarvisSafetyMode`: `allowlist` reuses the command-approval modal for risky/unknownactions; `trust` runs all. First-run disclaimer gates the tab (localStorage `laic.jarvisAccepted`).* **Jarvis orb** (`JarvisOrb.tsx`): a WebGL fragment shader (domain-warped fBm, hot core, fresnel rim, halo)with states idle/working/talking driven by uniforms; `pulse` (from real TTS `onboundary`) flashes it whiletalking. Falls back to a CSS orb (in `styles.css`) if WebGL is unavailable; honors reduced-motion.* **Design system** (`styles.css`): CSS custom properties for 4 themes (dark default on bare `:root`, plus`\\\\\\\[data-theme=light|terminal|highcontrast]`). Accent tints use `color-mix(in srgb, var(--accent) …)`.Key tokens: `--bg --panel --panel-2 --elevated --border --text --muted --accent --accent-2 --ok --warn --off --danger --on-accent --shadow --radius`. Style through tokens, not literals, so all themes track.\---## 5\. Expect a fix ortwo per provider on first run. Cloud model ids go stale — update on a 404.* Browser speech-to-text (🎤) likely won't work in Electron; TTS (🔊) will. Reliable offline dictation wouldneed a local Whisper engine (not built).* Shell command execution and Jarvis `run\\\\\\\_command` are gated/bounded but run real commands with the user's OSprivileges. Jarvis `open\\\\\\\_app` launches whatever the known-apps map points to.* Remote Ollama needs `OLLAMA\\\\\\\_HOST=0.0.0.0` + firewall open on that machine, or it's undetectable.* **Jarvis Stage 2** (native mouse/keyboard/screen control) is deferred — needs a real Windows desktop tobuild against; untestable in the Linux dev sandbox.* Git **tag** pushes are rejected by the dev environment's proxy (branch pushes are fine).
