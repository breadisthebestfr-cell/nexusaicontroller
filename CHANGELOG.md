# Changelog

All notable work on Nexus (formerly LocalAIConnection), newest first. Every entry was verified with
`npm test` + `npm run build` against the bundled mock Ollama (no real hardware needed).

## v0.3.0 — Nexus (2026-08)

The app is renamed **Nexus**, gains the **Jarvis** desktop assistant with a WebGL plasma orb, and gets a
cohesive violet UI refresh. **113 tests pass**; typecheck + build clean.

### Changed
- **UI refresh** — reworked the global stylesheet around the Nexus/orb identity: a violet-biased palette
  (all four themes) with a plasma-violet accent, gradient primary buttons and active tabs, layered panels
  with soft shadows and hover states, input focus rings, a live status chip, a subtle ambient glow behind
  the shell, themed scrollbars, and animated toasts. Added `--elevated`/`--warn`/`--on-accent`/`--shadow`
  tokens and accent-derived tints via `color-mix`. Honors `prefers-reduced-motion`.
- **Renamed the app to Nexus** — the project outgrew "LocalAIConnection" (it's now a command center for AI:
  local + cloud discovery/control, multi-agent orchestration, continuous mode, MCP, Discord, and the Jarvis
  assistant). Rebranded the window title, in-app header, onboarding, docs, `productName`/`appId`, and the
  Jarvis documents dir (`~/Nexus/`). The GitHub repo and internal `LOCALAI_*` env vars / code identifiers
  keep their old names for continuity. The assistant is still **Jarvis**.

### Added
- **Jarvis presence orb** — a real-time WebGL plasma sphere (domain-warped fBm filaments, hot core, fresnel
  rim, soft halo) that reacts to Jarvis's state: idle (calm swirl), working (faster/brighter/turbulent), and
  talking (breathes open/closed and flashes on each spoken word, driven by real TTS boundary events). Falls
  back to a CSS orb without WebGL; honors reduced-motion.
- **Shorter Jarvis replies** — the assistant now confirms in one very short spoken line ("On it, sir.")
  instead of explaining, since the reply is read aloud.
- **Jarvis — desktop assistant (Stage 1)** — a new **Jarvis** tab: type (or hear replies via 🔊) and a model
  (local or cloud, cloud preferred by default) can act on your PC. The model emits `ACTION:` directives that
  are parsed (`src/main/actions.ts`) and executed (`src/main/desktop.ts`): **open_app** (from an editable
  known-apps list in Settings), **open_url** (link or web search), **create_document** (saved to
  `~/Nexus/` and opened), **say**, and **run_command** (reuses the gated single-command runner).
  Two safety modes — **Allowlist** (unknown apps / commands need approval via the existing command modal) and
  **Trust** (runs without asking) — plus a one-time at-your-own-risk disclaimer gating the tab. Assistant name
  and known apps are configurable in Settings. **Stage 2** (native mouse/keyboard/screen control) is
  deferred — it needs a real Windows desktop to build against. 17 new tests (113 total).

## v0.2.0 — checkpoint (2026-08)

A stable save point. 96 tests passing; typecheck + build clean.

### Pre-test hardening (before first real run)
- Cloud model-id defaults refreshed (esp. Anthropic) — still verify them in Settings, ids change often.
- OpenAI `stream_options` is now sent only to real OpenAI, so xAI / OpenAI-compatible gateways don't 400.
- Anthropic `max_tokens` raised (4096 → 8192) to reduce mid-file truncation.
- Global toast notifications + a catch-all for renderer errors, and a helpful hint when a manually-added
  host is unreachable (likely `OLLAMA_HOST`/firewall).
- App icon (`build/icon.png`, generated by `scripts/gen-icon.mjs`) for the installer.

### Added since v0.1
- **Cloud providers** — optional OpenAI / Anthropic (Claude) / xAI (Grok) models alongside local Ollama,
  via API keys stored only on the local machine. They appear in Chat, Arena, and as agent roles.
- **Model Arena** — send one prompt to up to 4 models at once and compare answers side-by-side.
- **Speed & token stats** — tokens/sec + timing shown per chat reply (and per Arena column).
- **Continuous cycle diffs** — view the git patch for each autonomous cycle in the UI.
- **Agent shell commands (opt-in)** — coder can request commands via `RUN:`; single-command-only,
  allowlist + Approve / Approve-and-always-allow / Deny for interactive runs, allowlist-only when autonomous.
- **Voice mode** — 🔊 reads replies aloud (offline OS voices) and 🎤 best-effort dictation.
- **Concise chat style**, **drag-and-drop a file into chat**, **saved prompts/tasks library**.
- **Quality of life** — theme picker (dark/light/terminal/high-contrast), instance nicknames, history
  search + export + stats tiles, cancel-scan, remembered task/roles, input validation, `.env.example`.
- **First-run in-app tour** + `GETTING_STARTED.md`.
- **Bug-check pass** — fixed 7 correctness issues found in review (review-loop false-positive, file-block
  truncation on nested fences, stale-online after rescan, run-history write race, continuous stall signal,
  chat first-token race, settings deep-merge).

## Phase history (the original build)

- **V1** — LAN discovery + dashboard, manual add, single-model streaming chat, project-folder picker,
  settings, and a mock Ollama + tests.
- **V2** — planner → coder → reviewer collaboration loop writing files into the folder, live transcript,
  sandboxed file writes.
- **V3** — MCP server (`src/mcp/`) exposing `list_instances`, `list_models`, `ask_model`,
  `run_multi_agent_task` (+ later `notify`) so Claude Code can drive the local models.
- **V4** — live health polling, run history, and the small-model helper (tuned prompts, per-role
  temperature, format auto-repair).
- **V5** — continuous autonomous mode (external memory, git auto-commit per cycle, stall guard) and
  auto best-model selection.
- **V6** — Discord: outbound webhook notifications, a control bot (`!start`/`!stop`/`!status`), and the
  `notify` MCP tool; plus @-mention pings and a webhook self-test CLI.
- **V7** — agent shell commands (allowlist + approval).

## Known limits / not yet verified on real hardware
- Cloud provider calls follow the documented APIs but haven't been exercised against live endpoints;
  model ids in Settings are editable since they change over time.
- Browser speech-to-text often doesn't work in Electron — reliable offline dictation would need a local
  Whisper engine (future).
- Shell-command execution is gated and bounded, but still runs real commands with your OS privileges.
